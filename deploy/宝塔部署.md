# 宝塔面板部署指南

适用于已在服务器上装了**宝塔面板**的情况。核心思路：

> **中间件用命令行装（宝塔没有 Postgres），Python 项目和 Nginx 用宝塔图形界面管。**

> 📖 **本文是「要点速查版」**，适合装过一次之后回头查具体某步。
> **如果是第一次从零安装**，看 **[安装教程.md](安装教程.md)** —— 那份是完整的分步教程，
> 每步都带验证命令和期望输出，照着抄不会错。
>
> 🔧 **跑起来之后出错看 [排障指南.md](排障指南.md)** —— 讲清报错去哪找、
> 前端红字对应服务端哪个字段。最快的方式是先跑 `python deploy/doctor.py` 做一次体检。

如果按本文档走，`deploy/install.sh` **不要整个跑** —— 只借用它的第 1、4 步。

---

## 先解决数据库选择

你问能不能把 Postgres 换成 MySQL 或 SQLite。结论：

| 方案 | 可行性 | 说明 |
|---|---|---|
| **MySQL** | ✅ 可以，推荐 | 代码已做好兼容，改连接串即可。宝塔自带，省事 |
| **SQLite** | ❌ 不建议生产用 | 多进程写锁会冲突，Worker 会报 `database is locked`。只能本地开发 |
| Postgres | ✅ 可以，但要命令行装 | 宝塔软件商店没有 Postgres |

**建议用 MySQL。** 我已经把代码改成三种后端通吃，`tests/mysql.py` 验证过：
建表 DDL、索引长度、唯一约束、查询语句在 MySQL 方言下全部编译通过，无 Postgres 专有语法残留。

⚠️ 一个已知的性能取舍：列表搜索用的是 `ilike`，在 MySQL 下会生成
`lower(x) LIKE lower(y)`，**用不上索引会全表扫描**。你用户量小（几个朋友）完全无所谓，
上千条以上才需要考虑优化。

## 部署步骤

### 第 1 步：装系统依赖（命令行）

宝塔软件商店**没有 Postgres 和 ffmpeg**，这两个得命令行装：

```bash
apt update
apt install -y python3 python3-venv python3-pip ffmpeg
```

> **Redis 不用装** —— 你宝塔里已经有了，直接用。

验证：

```bash
python3 --version    # 需要 >= 3.10
ffmpeg -version | head -1
```

### 第 2 步：在宝塔建 MySQL 数据库

1. 宝塔面板 → **数据库** → 添加数据库
2. 数据库名：`bsum`
3. 用户名：`bsum`
4. 密码：点「随机」生成，**记下来**
5. **字符集务必选 `utf8mb4`** ← 这个很关键，选错中文和 emoji 会报错

### 第 3 步：上传代码

宝塔面板 → **文件** → 进入 `/www/wwwroot/` → 新建目录 `bsum`
→ 上传项目压缩包 → 解压

或者用命令行（把本地项目传上去）：

```bash
scp -r C:\Game\bilibili-summary-cloud root@你的服务器IP:/www/wwwroot/bsum
```

> **注意路径**：本文档统一用 `/www/wwwroot/bsum`。宝塔习惯把项目放这儿，
> 你在面板里操作也顺手。如果你的路径不同，后面所有地方都跟着改。

### 第 4 步：建 venv 并装依赖

宝塔 → **终端**（或 SSH）：

```bash
cd /www/wwwroot/bsum
python3 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

装依赖这步比较慢（要编译 `scikit-learn` 之类），耐心等。

### 第 5 步：写配置文件

```bash
cd /www/wwwroot/bsum
cp .env.example .env
```

生成两个密钥：

```bash
# Fernet 密钥（加密用户凭证）
.venv/bin/python -c "from cryptography.fernet import Fernet; print('SECRET_KEY=' + Fernet.generate_key().decode())"

# JWT 密钥
echo "JWT_SECRET=$(openssl rand -hex 32)"
```

把输出填进 `.env`。然后改这几个关键项：

```ini
APP_ENV=production
APP_BASE_URL=http://你的服务器IP或域名

# 刚才生成的
SECRET_KEY=...
JWT_SECRET=...

# 第 2 步在宝塔建的（注意密码替换成真实的，charset 必须 utf8mb4）
DATABASE_URL=mysql+aiomysql://bsum:你的密码@127.0.0.1:3306/bsum?charset=utf8mb4
DATABASE_URL_SYNC=mysql+pymysql://bsum:你的密码@127.0.0.1:3306/bsum?charset=utf8mb4

# 宝塔的 Redis（默认端口 6379，没设密码就这样；设了密码用 redis://:密码@127.0.0.1:6379/0）
REDIS_URL=redis://127.0.0.1:6379/0

# 管理员密码，首次启动会用这个建账号，登录后请立刻改
ADMIN_USERNAME=admin
ADMIN_PASSWORD=换成你自己的强密码
```

然后收紧权限：

```bash
chmod 600 /www/wwwroot/bsum/.env
```

### 第 6 步：初始化数据库

```bash
cd /www/wwwroot/bsum
.venv/bin/python -m app.bootstrap
```

看到输出里 `settings=20`、`admin存在=True` 就成功了。这一步做的事：
建表 → 写默认配置 → 建管理员账号。**可以重复执行**，不会重复建。

如果报 `Access denied`，回去检查 `.env` 里的数据库密码。

### 第 7 步：宝塔加两个 Python 项目

宝塔面板 → **网站** → **Python 项目** → 添加项目。

> **推荐做法：只加一个项目，用 `bt_start.sh` / `bt_stop.sh`（见下方 8.1 之前的说明）。**
> 下面「项目一 + 项目二」是两个项目分开管的老方案，仍然可用，但宝塔对
> 「一个项目对应多个进程」支持得不好，容易出现 Worker 变孤儿进程的问题。

#### 方案 A（推荐）：单项目 + 启动脚本

宝塔只加 **一个** Python 项目，脚本内部同时拉起 Web 和 Worker：

| 项 | 填什么 |
|---|---|
| 项目名称 | `bsum` |
| 项目路径 | `/www/wwwroot/bsum` |
| Python 版本 | 选你系统那个（3.10 或 3.12） |
| 启动方式 | **自定义命令** |
| 启动命令 | `bash /www/wwwroot/bsum/deploy/bt_start.sh` |
| 停止命令 | `bash /www/wwwroot/bsum/deploy/bt_stop.sh` |
| 端口 | `8000` |
| 运行用户 | `www` |
| 是否安装依赖 | **否**（第 4 步已经装了） |
| 开机自启 | ✅ 勾上 |

**为什么这样做：**

宝塔靠「启动命令拉起的那个前台进程的 PID」判断项目存活。
`bt_start.sh` 的处理方式是：

- **Web** 用 `exec` 前台接管 → uvicorn 的 PID 与脚本 PID 一致，宝塔能正确判活
- **Worker** 用 `nohup` 后台拉起，PID 写进 `.run/worker.pid`，
  由 `bt_stop.sh` 负责收掉

如果分成两个宝塔项目，Worker 那个项目宝塔倒是能管，
但很多人只加 Web 项目忘了加 Worker，结果任务永远卡在「排队中」。
单项目方案把这件事变成一个脚本，少一个遗忘点。

`bt_start.sh` 还会：
- 启动前自动跑一次 `app.bootstrap`（幂等，建表 + 补默认配置）
- 启动前清理残留的旧 Worker（按 PID 文件）
- 启动后等 2 秒确认 Worker 没立刻崩，崩了就把日志尾巴打出来

`bt_stop.sh` 会：
- 按 PID 文件优雅停止 Worker，15 秒不退则 `kill -9`
- 用 `pgrep` 兜底清理 WorkerPool fork 出来的子进程
- 清理 `temp/` 里的下载中转文件（崩溃时可能留下大文件）

#### 方案 B：两个项目分开管

<details>
<summary>点开看旧方案（仍可用）</summary>

**项目一：Web 服务**

| 项 | 填什么 |
|---|---|
| 项目名称 | `bsum-web` |
| 项目路径 | `/www/wwwroot/bsum` |
| 框架 | `其他` |
| 启动方式 | `uvicorn` |
| 启动文件 | `app.main:app` |
| 端口 | `8000` |
| 运行用户 | `www` |
| 是否安装依赖 | **否** |
| 开机自启 | ✅ 勾上 |

填不明白就用「自定义命令」：`bash /www/wwwroot/bsum/deploy/run.sh web`

**项目二：Worker 服务**

| 项 | 填什么 |
|---|---|
| 项目名称 | `bsum-worker` |
| 启动方式 | **自定义命令** |
| 启动命令 | `bash /www/wwwroot/bsum/deploy/run.sh worker` |
| 端口 | 留空（Worker 不监听端口） |
| 开机自启 | ✅ 勾上 |

> **Worker 必须单独起**，不跑的话任务会一直卡在「排队中」。

</details>

#### 关于开机自启与环境变量

宝塔的 Python 项目管理器会给每个项目生成 systemd unit。它**默认不加载 `.env`**，
但我们的代码里 `app/core/config.py` 是按绝对路径主动读 `.env` 的，
所以**不用管环境变量**，能正常工作。

如果宝塔界面里有「环境变量」输入框，留空即可。

### 第 8 步：配 Nginx 反向代理

宝塔 → **网站** → 添加站点（用你的域名或服务器 IP）。

然后点这个站点 → **反向代理** → 添加：

| 项 | 填什么 |
|---|---|
| 代理名称 | `bsum` |
| 目标 URL | `http://127.0.0.1:8000` |
| 发送域名 | `$host` |

添加完之后，**必须手动改配置加 SSE 关缓冲**，宝塔的界面点不出来。

点站点 → **配置文件**，在 `location ~ ^/api/` 之类的反代块里加上这三行：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_set_header X-Accel-Buffering no;
```

并把超时调长：

```nginx
proxy_read_timeout 1800s;
proxy_send_timeout 1800s;
gzip off;
```

**⚠️ 这一步不做的话，任务进度条会一直卡着不动。** 因为进度走 SSE 流式推送，
Nginx 默认会缓冲响应，把「实时进度」攒成「最后一次性吐出」。

参考 `deploy/nginx.conf`，里面有完整示例，直接对照着抄。

改完保存，宝塔会自动 reload Nginx。

## 部署后

访问 `http://你的域名/` → 用 `.env` 里的管理员账号登录 → 进 `/admin` 配密钥：

| 配置项 | 说明 |
|---|---|
| DeepSeek API Key | 总结用的模型 |
| COS SecretId / SecretKey / 地域 / 存储桶 | 腾讯云对象存储 |
| ASR SecretId / SecretKey / 地域 | 腾讯云语音识别 |

**COS 地域必须和服务器地域一致**，否则 ASR 拉音频走公网会产生流量费。

## 排障

### 任务一直「排队中」

Worker 没跑起来。宝塔 → Python 项目 → 看 `bsum-worker` 状态与日志。

手动测一下：

```bash
cd /www/wwwroot/bsum
bash deploy/run.sh worker
```

### 进度条卡住不动

99% 是 Nginx 缓冲没关。检查站点配置文件里有没有那三行 SSE 关缓冲指令。

### 数据库报错

```bash
# 手动测 MySQL 连通
cd /www/wwwroot/bsum
.venv/bin/python -c "
import asyncio, os
os.chdir('/www/wwwroot/bsum')
from app.db.session import engine
from sqlalchemy import text
async def t():
    async with engine.connect() as c:
        r = await c.execute(text('SELECT VERSION()'))
        print('MySQL 版本:', r.scalar())
asyncio.run(t())
"
```

常见原因：字符集不是 `utf8mb4`、密码错、或宝塔没给 `bsum` 用户
`127.0.0.1` 的访问权限（宝塔建库时默认给 `localhost`，
如果连不上就在宝塔里把「访问权限」改成「所有人」或加 `127.0.0.1`）。

### 中文乱码 / emoji 报错

```sql
-- 检查库的字符集
SHOW CREATE DATABASE bsum;
```

必须是 `utf8mb4`。如果是 `utf8`（MySQL 的坑，它只有 3 字节），要重建库：

```sql
ALTER DATABASE bsum CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 内存吃紧

2 核 4G 正常不会。如果真的紧张，把 Worker 并发降到 1：
宝塔 Python 项目 → `bsum-worker` → 环境变量加 `WORKER_CONCURRENCY=1`。

### 日志在哪

- **应用日志**：`/www/wwwroot/bsum/logs/`
- **宝塔项目日志**：Python 项目管理器里每个项目都有「日志」按钮
- **Nginx 日志**：宝塔 → 网站 → 站点 → 日志

## 顺便说一句：宝塔 vs 我给的 install.sh

两种方式不冲突，各有各的好：

| | 宝塔面板 | `deploy/install.sh` |
|---|---|---|
| 图形界面 | ✅ 直观 | ❌ 纯命令行 |
| Postgres | ❌ 商店没有 | ✅ 自动装 |
| 进程守护 | ✅ 面板里点 | ✅ systemd |
| 配置可复现 | ❌ 手点的，容易漏 | ✅ 脚本化，可重跑 |
| **SSE 关缓冲** | ❌ **界面点不出来，必须手动改** | ✅ 已写好 |

**你现在的情况用宝塔更合适**，因为你 Redis 已经在宝塔里了，
统一管理比一半图形一半命令行清爽。只要记得 SSE 那三行**必须手动加**就行。
