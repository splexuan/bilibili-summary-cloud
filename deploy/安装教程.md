# 安装教程（从零开始）

> 场景：你手上有一台**全新的腾讯云轻量服务器**（2 核 4G），已经装好**宝塔面板**，
> Redis 也已经在宝塔里装好了。别的什么都没有。
>
> 全程照抄即可。每一步都有**验证方法**，报错了往下找「排障」章节。
>
> 🔧 装完之后运行时出错，看 **[排障指南.md](排障指南.md)**；
> 或者直接跑 `python deploy/doctor.py` 做一次一体检。

预计耗时：**40～60 分钟**，其中一半是等 pip 编译依赖。

## 第 0 步：开工前的三件事

### 1. 确认服务器能连外网

```bash
curl -I https://pypi.org
```

看到 `HTTP/2 200` 就行。**必须能连外网** —— 装依赖、调 DeepSeek、传 COS 全靠它。

### 2. 确认系统版本

```bash
cat /etc/os-release | head -2
uname -m
```

- 系统：Ubuntu 20.04 / 22.04 / 24.04 或 Debian 11/12 都行
- 架构：`x86_64`。**如果是 `aarch64`（ARM）**，注意有些包可能没有预编译 wheel，装依赖会慢很多，但能装

### 3. 记下四个「服务器事实」

填好这张表，后面到处要用：

| 项目 | 你的值 | 从哪来 |
|---|---|---|
| 服务器 IP | `____.__.__.__` | 腾讯云控制台 |
| SSH 端口 | `22`（默认） | 腾讯云控制台 → 防火墙 |
| 宝塔面板地址 | `http://IP:8888/xxxxxx` | 装宝塔时输出的 |
| 服务器地域 | `ap-guangzhou` 等 | 腾讯云控制台 → 轻量服务器详情 |

> ⚠️ **地域这一项很关键**，第 10 步配 COS 时必须和它一致，否则会产生外网流量费。
> 现在先记下来。

### 4. 放行端口

腾讯云控制台 → 你的轻量服务器 → **防火墙**，确认放行：

| 端口 | 用途 |
|---|---|
| `22` | SSH |
| `8888` | 宝塔面板 |
| `80` | HTTP（你的站点） |
| `443` | HTTPS（有域名的话，可选） |

> `8000` **不要**放行。Web 服务只监听 `127.0.0.1:8000`，对外统一走 Nginx。
> 放行了反而让人能绕过 Nginx 直接访问，没必要。

## 第 1 步：装系统依赖（ffmpeg + Python）

宝塔软件商店里**没有 ffmpeg，也没有 Postgres**，这两个必须用命令行装。

打开宝塔面板 → 左侧 **终端**，或者用你自己的 SSH 工具连上去，执行：

```bash
apt update
apt install -y python3 python3-venv python3-pip ffmpeg curl ca-certificates
```

> **Redis 不用装。** 你宝塔里已经有了，直接用。
> **MySQL 不用装。** 第 2 步在宝塔里建。

装的过程会问 `Do you want to continue? [Y/n]`，敲 `y` 回车。

### 验证

```bash
python3 --version
ffmpeg -version | head -1
python3 -c "import venv; print('venv OK')"
```

期望输出类似：

```
Python 3.10.12          ← 必须是 3.10 或更高
ffmpeg version 5.1.6    ← 有版本号就行
venv OK
```

> **如果 `python3 --version` 低于 3.10**（比如 Debian 11 是 3.9），代码跑不起来。
> Ubuntu 22.04 是 3.10，24.04 是 3.12，都能用。
> Debian 11 需要额外装新版 Python，参考文末「排障 → Python 版本太低」。

## 第 2 步：在宝塔建 MySQL 数据库

宝塔面板 → 左侧 **数据库** → 上方 **添加数据库**。

| 字段 | 填什么 |
|---|---|
| 数据库名 | `bsum` |
| 用户名 | `bsum` |
| 密码 | 点右边的「随机」按钮生成，**复制下来存好** |
| 数据库编码 | **`utf8mb4`** ← 千万别选错 |
| 访问权限 | `本地服务器`（默认即可） |

### ⚠️ 为什么必须是 utf8mb4

MySQL 的 `utf8` 是个历史坑 —— 它**只有 3 字节**，存不下 emoji 和部分生僻字。
选成 `utf8` 的话，视频标题里带个 emoji 就会报：

```
Incorrect string value: '\xF0\x9F...' for column 'title'
```

`utf8mb4` 才是真正的 UTF-8（4 字节）。**建库时选对，比事后改库省事一万倍。**

### 验证

建完之后，在宝塔的数据库列表里能看见 `bsum`。或者命令行验证：

```bash
mysql -ubsum -p -e "SHOW CREATE DATABASE bsum\G" 
```

> 提示 `mysql: command not found` 也没关系，宝塔的 MySQL 自带客户端路径比较深，
> 这一步跳过，第 6 步能连上就说明库建对了。

确认输出里有 `CHARACTER SET utf8mb4`。

## 第 5 步：生成配置文件

### 5.1 复制模板

```bash
cd /www/wwwroot/bsum
cp .env.example .env
```

### 5.2 生成两个密钥

这两个密钥**必须是随机生成的**，不能用手抄的。在终端里跑：

```bash
cd /www/wwwroot/bsum

echo "────── 下面两行，复制到 .env 里 ──────"
.venv/bin/python -c "from cryptography.fernet import Fernet; print('SECRET_KEY=' + Fernet.generate_key().decode())"
echo "JWT_SECRET=$(openssl rand -hex 32)"
```

输出长这样（你的会不一样）：

```
────── 下面两行，复制到 .env 里 ──────
SECRET_KEY=8Kx3vQ2mNp7LwZ9aBcDeFgHiJkLmNoPqRsTuVwXyZ012=
JWT_SECRET=3f8a2b1c9d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c7d8e9f0
```

> **这两个密钥的作用：**
> - `SECRET_KEY` 加密用户在后台填的 DeepSeek Key 和 B 站 Cookie 存进数据库。
>   **一旦换掉，之前加密的数据全部解不开**，用户得重填。
> - `JWT_SECRET` 给登录令牌签名。换掉等于所有人被强制登出。
>
> 所以：**生成一次，存到你的密码管理器里，别再改。**

### 5.3 编辑 .env

宝塔 → **文件** → 进 `/www/wwwroot/bsum` → 找到 `.env` → 双击编辑。

改这几个值：

```ini
# ─── 运行环境 ───
APP_ENV=production
APP_BASE_URL=http://你的服务器IP
# 有域名就写域名的域名，比如 http://bsum.example.com

# ─── 安全（填 5.2 生成的两行）───
SECRET_KEY=粘这里
JWT_SECRET=粘这里

# ─── 数据库（密码换成第 2 步宝塔生成的那个）───
DATABASE_URL=mysql+aiomysql://bsum:你的密码@127.0.0.1:3306/bsum?charset=utf8mb4
DATABASE_URL_SYNC=mysql+pymysql://bsum:你的密码@127.0.0.1:3306/bsum?charset=utf8mb4

# ─── Redis（宝塔的，没设密码就这样；设了密码见下方说明）───
REDIS_URL=redis://127.0.0.1:6379/0

# ─── 管理员账号（首次启动时创建）───
ADMIN_USERNAME=admin
ADMIN_PASSWORD=换成一个你自己的强密码
```

**几个高频坑：**

| 坑 | 说明 |
|---|---|
| 数据库密码里的特殊字符 | 密码含 `@` `:` `/` `#` 会截断 URL。**用宝塔「随机」生成的密码**（只含字母数字）最省事 |
| Redis 有密码 | 格式变成 `redis://:你的密码@127.0.0.1:6379/0`，**注意冒号位置** |
| `?charset=utf8mb4` | 一定要带，丢了可能乱码 |
| `ADMIN_PASSWORD` | 这是**首次建号**用的。改这个不会改已存在的账号密码 |

### 5.4 收紧权限

`.env` 里有数据库密码和密钥，别让别的用户读到：

```bash
chmod 600 /www/wwwroot/bsum/.env
```

### 验证

```bash
cd /www/wwwroot/bsum
grep -E "^(APP_ENV|DATABASE_URL|REDIS_URL|ADMIN_USERNAME)=" .env
```

确认 `APP_ENV=production`、`DATABASE_URL` 是 mysql 开头、密码是对的。

## 第 7 步：加 Python 项目

**这是整个安装最容易出错的一步，看清楚。**

服务是**两个进程**：

| 进程 | 干什么 | 不跑的后果 |
|---|---|---|
| **Web** | 处理 HTTP 请求、SSE 推流 | 网站打不开 |
| **Worker** | 干重活：下载视频、调 ASR、调 AI 总结 | 网站能开，但任务**永远卡在「排队中」** |

### 推荐：只加一个项目，用启动脚本兜住两个进程

宝塔对「一个项目对应多个进程」支持得不好 —— 它靠**前台进程的 PID** 判断项目存活，
而 Worker 必须是后台进程。`deploy/bt_start.sh` 把这件事处理掉了：

- **Web** 用 `exec` 前台接管 → PID 与宝塔记录的一致，能正确判活
- **Worker** 用 `nohup` 后台拉起，PID 写进 `.run/worker.pid`，由 `bt_stop.sh` 收掉

宝塔面板 → 左侧 **网站** → **Python 项目** → **添加项目**，只加**一个**：

| 字段 | 填什么 |
|---|---|
| 项目名称 | `bsum` |
| 项目路径 | `/www/wwwroot/bsum` |
| Python 版本 | 选系统那个（3.10 或 3.12） |
| 启动方式 | **自定义命令** |
| 启动命令 | `bash /www/wwwroot/bsum/deploy/bt_start.sh` |
| 停止命令 | `bash /www/wwwroot/bsum/deploy/bt_stop.sh` |
| 端口 | `8000` |
| 运行用户 | `www` |
| 是否安装依赖 | **否**（第 4 步已经装好了） |
| 开机自启 | ✅ **勾上** |

`bt_start.sh` 额外做的事：

1. 启动前自动跑一次 `app.bootstrap`（幂等：建表 + 补默认配置 + 建管理员）
2. 启动前清理残留的旧 Worker（按 `.run/worker.pid`）
3. Worker 拉起后等 2 秒确认没立刻崩；崩了就把日志尾巴打出来并退出

`bt_stop.sh` 额外做的事：

1. 按 PID 文件优雅停止 Worker，15 秒不退则 `kill -9`
2. 用 `pgrep` 兜底清理 WorkerPool fork 出的子进程（防孤儿进程占着队列和内存）
3. 清理 `temp/` 里的下载中转文件

> 想自己看这两个脚本做了什么：
> ```bash
> cat /www/wwwroot/bsum/deploy/bt_start.sh
> cat /www/wwwroot/bsum/deploy/bt_stop.sh
> ```

### 备选：两个项目分开管

如果宝塔界面里没有「停止命令」这一栏，或者你想分别看到两个进程的状态，
那就加两个项目：

**项目一：Web 服务**

| 字段 | 填什么 |
|---|---|
| 项目名称 | `bsum-web` |
| 项目路径 | `/www/wwwroot/bsum` |
| Python 版本 | 选系统那个 |
| 启动方式 | **自定义命令** |
| 启动命令 | `bash /www/wwwroot/bsum/deploy/run.sh web` |
| 端口 | `8000` |
| 运行用户 | `www` |
| 是否安装依赖 | **否** |
| 开机自启 | ✅ **勾上** |

**项目二：Worker 服务**

| 字段 | 填什么 |
|---|---|
| 项目名称 | `bsum-worker` |
| 项目路径 | `/www/wwwroot/bsum` |
| 启动方式 | **自定义命令** |
| 启动命令 | `bash /www/wwwroot/bsum/deploy/run.sh worker` |
| 端口 | **留空**（Worker 不监听端口） |
| 运行用户 | `www` |
| 是否安装依赖 | **否** |
| 开机自启 | ✅ **勾上** |

> ⚠️ 这个方案最常见的翻车是「只加了 Web，忘了加 Worker」，
> 表现就是任务永远卡在「排队中」。

### 为什么用脚本而不是直接填命令

宝塔的 uvicorn 表单在不同版本里字段名不一样，填错了很难排查。脚本做的事：

1. 自动 `cd` 到项目根目录（**宝塔执行时工作目录可能不是项目根，这是最常见的坑**）
2. 用 `.venv/bin/python` 这个绝对路径（不依赖 PATH）
3. Web 只监听 `127.0.0.1:8000`（对外走 Nginx）

内容很短，你可以自己打开看：

```bash
cat /www/wwwroot/bsum/deploy/bt_start.sh
```

### 关于「环境变量」输入框

宝塔这个框**留空**即可。

原因：宝塔生成的 systemd unit 不加载 `.env`，但我们的 `app/core/config.py`
第 19 行是按**绝对路径**读 `.env` 的：

```python
env_file=str(BASE_DIR / ".env")   # BASE_DIR 是项目根，和当前工作目录无关
```

所以配置文件一定能读到，不用管环境变量。

### 验证：两个进程都起来了

在宝塔 Python 项目列表里，两个项目都应该是 **运行中**。

命令行再确认一下：

```bash
ps aux | grep -E "uvicorn|app.workers.worker" | grep -v grep
```

期望看到**两行**（一个是 uvicorn，一个是 worker）。

再看 Web 有没有真的监听：

```bash
curl -s -o /dev/null -w "HTTP %{http_code}\n" http://127.0.0.1:8000/api/health
```

输出 `HTTP 200` 就对了。

## 第 8 步：配 Nginx 反向代理（含 SSE 关键设置）

**这一步有个必须手动做的事，宝塔界面上点不出来。漏了的话任务进度条会一直卡着不动。**

### 8.1 添加站点

宝塔 → **网站** → **添加站点**：

| 字段 | 填什么 |
|---|---|
| 域名 | 你的域名；没域名就填服务器 IP |
| 根目录 | 默认即可（我们不用它放文件） |
| PHP 版本 | **纯静态** |

### 8.3 ⚠️ 手改配置加 SSE 关缓冲（关键！）

宝塔的反向代理界面**没有**关缓冲的选项，必须手动改配置文件。

点站点 → 左侧 **配置文件**，找到反代产生的 `location` 块，改成这样：

```nginx
location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;

    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade           $http_upgrade;
    proxy_set_header Connection        "";

    # ═══ 这三行是 SSE 实时进度条的生命线，缺一不可 ═══
    proxy_buffering off;
    proxy_cache off;
    proxy_set_header X-Accel-Buffering no;

    # ═══ 长任务：总结一个长视频可能跑十几分钟 ═══
    proxy_read_timeout 1800s;
    proxy_send_timeout 1800s;
    chunked_transfer_encoding on;
    gzip off;
}
```

保存。宝塔会自动 reload Nginx。

### 为什么这三行是必须的

进度条走的是 **SSE（Server-Sent Events）** —— 服务器持续往浏览器推「当前进度 30%」这种小消息。

Nginx **默认会缓冲响应**，把「一条一条推」攒成「最后一次性吐出」。结果就是：
浏览器一直收不到消息，进度条**卡在 0% 纹丝不动**，直到任务跑完才突然跳到 100%。

`proxy_buffering off` 关掉缓冲，`X-Accel-Buffering: no` 是给上游一个明确信号，
两个都要。`gzip off` 是因为压缩也会引入缓冲。

> 完整可对照的配置样例在 `deploy/nginx.conf`，可以直接抄。

## 第 10 步：在后台配密钥

|---|---|
| DeepSeek API Key | `sk-` 开头的那串，从 [platform.deepseek.com](https://platform.deepseek.com) 拿 |

### 腾讯云 COS（对象存储）

| 配置项 | 填什么 |
|---|---|
| COS SecretId | 腾讯云访问密钥 |
| COS SecretKey | 同上 |
| COS 地域 | **必须和第 0 步记的服务器地域一致** |
| COS 存储桶 | `你的桶名-125xxxxxxx`（带 APPID 后缀的完整名） |

### 腾讯云 ASR（语音识别）

| 配置项 | 填什么 |
|---|---|
| ASR SecretId | 同上（可复用同一对密钥） |
| ASR SecretKey | 同上 |
| ASR 地域 | 和 COS 保持一致 |

### ⚠️ 三条必须知道的

**1. COS 地域必须和服务器地域一致**

音频文件的流转是：`服务器 → COS → ASR`。如果 COS 在别的城市，
ASR 拉音频要走公网，**按外网下行流量计费**。同地域走内网，免费。

启动时如果两个地域不一致，日志里会有警告：

```
COS 地域（ap-beijing）与 ASR 地域（ap-guangzhou）不一致，ASR 拉取音频可能产生外网下行流量费用
```

看到就去后台改回来。

**2. ASR 结果是 24 小时后过期的**

腾讯云 ASR 的识别结果**只保留 24 小时**。代码里已经做了处理 —— 识别完立刻
落库到 `videos.transcript`。但如果你手工去调腾讯云 API 做实验，记得这个限制。

**3. 别开付费的返回格式**

`ASR_RES_TEXT_FORMAT` 保持 `3`（按标点分段）。
`4`（语义分段）和 `5`（口语转书面语）是**增值付费项**，不在免费额度里。

### 配完验证

在首页提交一个**短视频**（3～5 分钟，B 站有字幕的那种）：

1. 进度条应该从 0 开始慢慢涨
2. 走完能看到总结
3. 因为有字幕，**不会消耗 ASR 额度**（优先用字幕，ASR 只是兜底）

再提交一个**没字幕**的视频，这次会走 ASR，可以在后台看到用量统计。

## 排障速查

### 任务一直卡在「排队中」

**原因**：Worker 没跑起来。

```bash
# 1. 看 worker 进程在不在
ps aux | grep app.workers.worker | grep -v grep

# 2. 手动前台跑，直接看报错
cd /www/wwwroot/bsum
bash deploy/run.sh worker
```

前台跑的时候报错最清楚。常见原因：

| 报错 | 原因 | 解决 |
|---|---|---|
| `Connection refused` Redis | Redis 没起或端口不对 | 宝塔 → 软件商店 → Redis → 确认运行中 |
| `Access denied for user` | `.env` 数据库密码错 | 核对第 2 步的密码 |
| `ModuleNotFoundError` | 依赖没装全 | 重跑 `.venv/bin/pip install -r requirements.txt` |
| `找不到虚拟环境` | `.venv` 路径不对 | 确认 `/www/wwwroot/bsum/.venv/bin/python` 存在 |

### 网页打不开 / 502

```bash
# Web 进程在不在
ps aux | grep uvicorn | grep -v grep

# 直接打后端，绕过 Nginx
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/api/health
```

- 后端 200 但网页 502 → **Nginx 配置问题**，检查反代目标是不是 `http://127.0.0.1:8000`
- 后端也连不上 → Web 进程挂了，看宝塔项目日志

### 进度条卡在 0% 不动

**99% 是 Nginx 缓冲没关。** 回去看第 8.3 步，确认配置文件里有这三行：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_set_header X-Accel-Buffering no;
```

改完记得保存（宝塔会自动 reload）。

自测一下 SSE 到底通不通：

```bash
curl -N -H "Accept: text/event-stream" "http://127.0.0.1:8000/api/job/1/stream?token=xxx"
```

`-N` 是禁用 curl 自己的缓冲。如果这里能持续收到数据、走 Nginx 收不到，
就一定是 Nginx 缓冲问题。

### 中文乱码 / emoji 报错

```
Incorrect string value: '\xF0\x9F...'
```

库的字符集不是 `utf8mb4`。检查：

```sql
SHOW CREATE DATABASE bsum;
```

如果显示 `utf8`（3 字节），改成：

```sql
ALTER DATABASE bsum CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**注意：改库不改已有表。** 已经建的表要一起改：

```sql
ALTER TABLE videos CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
-- 其他表同理，或者干脆删表重建（数据还在的话先备份）
```

最省事的办法：删库重建（此时还没数据），确认字符集选对再重跑第 6 步。

### 数据库连不上

```bash
cd /www/wwwroot/bsum
.venv/bin/python -c "
import asyncio, os
os.chdir('/www/wwwroot/bsum')
from app.db.session import engine
from sqlalchemy import text
async def t():
    async with engine.connect() as c:
        r = await c.execute(text('SELECT VERSION()'))
        print('MySQL 版本:', r.scalar())
asyncio.run(t())
"
```

报 `Access denied` 的话，检查两件事：

1. `.env` 里的密码对不对
2. **宝塔建库时给的访问权限是不是只有 `localhost`**。
   去 宝塔 → 数据库 → `bsum` → 点「权限」，改成 `所有人` 或者加上 `127.0.0.1`

### 内存吃紧 / 被 OOM 杀掉

2 核 4G 正常够用（各组件预算：Web ~200MB、Worker ~500MB、MySQL ~400MB、
Redis ~50MB、系统 ~500MB，合计约 1.7G）。

真的紧张就把并发降下来：

宝塔 → Python 项目 → `bsum-worker` → 环境变量加：

```
WORKER_CONCURRENCY=1
```

重启项目生效。代价是同时只能跑一个任务。

### Python 版本太低

Debian 11 自带 3.9，跑不起来。装 3.11：

```bash
add-apt-repository -y ppa:deadsnakes/ppa

rm -rf .venv              # ⚠️ 只删虚拟环境目录，别删错
python3.11 -m venv .venv
.venv/bin/pip install --upgrade pip
.venv/bin/pip install -r requirements.txt
```

> ⚠️ `rm -rf .venv` 只删这个目录。**千万别手滑写成 `rm -rf /www/wwwroot/bsum`。**
